# Example patient imports

The five profiles `99001`–`99005` contain **synthetic test data only**. The
de-identified validation traces `99006` and `99007` are derived from real ward
monitor recordings. All seven files are software test fixtures, not clinical
records; none may be used for clinical decisions.

Use **Admin → Import patient data** to load these files into a temporary,
browser-only cohort. The import derives a temporary ID from the numeric filename
prefix, validates recognized observations, and makes each profile available
from the dashboard. No patient rows or observations are written to Supabase.
Imports are read-only and are cleared when the browser tab reloads or closes;
the admin page and dashboard also provide an explicit clear action.

The `autoregulation_samples` property is Fisher-style JSON accepted
by the **/autoreg** study page. Add each file as a study recording there to run
the browser analysis. `autoreg_data` contains the corresponding seven-channel
request shape documented by OptiBrain; the temporary import does not send it to
OptiBrain or create a `patient_autoregulation` result.

| File | Scenario | Autoregulation signals |
|---|---|---|
| `99001_well.json` | Stable illustrative observations | PIC / PAM / PPC (PRx) |
| `99002_concerning.json` | Concerning illustrative observations | PIC / PAM / PPC (PRx) |
| `99003_critical.json` | Critical illustrative observations | PIC / PAM / PPC (PRx) |
| `99004_cox.json` | NIRS and arterial-pressure recording | NIRS / PAM (COx) |
| `99005_prx.json` | Intracranial-pressure recording | PIC / PAM / PPC (PRx) |
| `99006_deidentified_prx.json` | De-identified ward trace with complete local PPC-optimum windows | PIC / PPC |
| `99007_deidentified_cox.json` | De-identified ward trace from a saved COx analysis | NIRS / PAM |

These files exercise import and visualization code paths; their values and
calculated indices are not validated clinical profiles or treatment targets.

The synthetic examples contain deterministic, seeded monitoring data with
time-correlated measurement noise, intermittent labs, brief missing
measurements, and scenario-specific sustained events. Profiles `99001`–`99003`
cover six hours. Profiles `99004` and `99005` cover 24 hours; their analysis
channels use irregular, non-repeating pressure plateaus whose order and dwell
times vary from hour to hour. The profiles add small seeded noise and gentle
trends (rising PIC for PRx, falling NIRS for COx, and declining PPC/PAM), rather
than cycling through the same waveform. The displayed PIC/PPC/PAM/NIRS traces
use light exponential smoothing for readability, while `autoreg_data` retains
the analysis samples. Regression tests run the same browser-local calculation
and frontend window lookup used by temporary imports; they require at least
80% of displayed pressure samples to have a valid dynamic window and at least
one continuous visible span of three hours. The pressure excursions and
correlation patterns are intentionally engineered to exercise the UI and
calculation; they are not physiological models. The files are generated by
[`scripts/generate_example_patients.py`](../scripts/generate_example_patients.py);
the waveforms are synthetic test signals, not patient recordings or validated
physiological models.

## De-identified validation traces

The `99006` and `99007` files contain monitor values from ward recordings,
resampled to one-minute medians. Patient IDs, names, demographics, and source
timestamps are omitted; timestamps are shifted to 2020-01-01. The files are
still derived from real clinical data, are not synthetic, and should remain
inside the authorized development environment. The temporary-import UI labels
these separately from synthetic examples. Both are read-only software test
fixtures and are not for clinical use.

`99006_deidentified_prx.json` contains 1,253 paired one-minute PIC/PPC
observations and native PAM. The local browser analysis computes over 50
complete rolling PPC-optimum windows from this trace. The production OptiBrain
PRx endpoint was also tested on the same 24-hour source interval; it returned
3,085 recap rows but no non-null optimal PPC or limits. The displayed window
therefore demonstrates the corrected browser-local PIC/PPC calculation, not a
production OptiBrain result.

`99007_deidentified_cox.json` contains matched NIRS/PAM observations from the
ward patient whose saved production COx result had the largest raw result
table at extraction time. It contains 9,829 paired minute samples spanning
roughly 164 hours. That stored result contains over 1,300 complete time-varying
COx windows. Running the production endpoint on the fixture's latest 24 hours
(1,432 matched NIRS/PAM samples) returned 1,440 recap rows, 1,356 with an
optimum and both limits. The exported signal timestamps are shifted; the
example does not include an actual patient identifier or demographics.

## Autoregulation algorithms

### Production OptiBrain processing

The ward worker reads source monitoring records, rather than deriving
autoregulation from the chart's minute-level cache. It currently evaluates
the preceding 24 hours every sync cycle (nominally every 15 minutes). A patient
is submitted only when each required channel has at least 120 samples spanning
at least two hours:

| Mode | Required channels | Pressure axis | Correlated signals |
|---|---|---|---|
| PRx | PIC and PPC | PPC | PIC versus PPC |
| COx | NIRS and PAM (or cuff PAM) | PAM | NIRS versus PAM |

The implementation's PRx configuration specifically correlates PIC with PPC
(not PIC with arterial PAM); COx correlates NIRS with PAM. The OptiBrain
service resamples PRx input to 28-second intervals and COx input to 60-second
intervals. Missing observations remain missing until the module's resampling
and filtering steps; the worker does not infer a missing PPC channel.

For each mode, OptiBrain computes rolling Pearson correlations over 5, 10, 15,
30, 60, and 90-minute windows. It applies a rolling three-minute median to the
pressure signal and Fisher-transforms the correlations. Each three-minute
update then evaluates overlapping pressure windows: 2, 4, 8, 12, and 24 hours
for PRx; 1, 2, 4, 8, 12, and 24 hours for COx.

Inside each pressure window, the module:

1. Applies a two-minute rolling median to the pressure axis.
2. Groups pressure/index observations into 5 mmHg PRx bins or 3 mmHg COx bins.
   Bins holding 2% or less of the data are excluded, as are the extreme
   pressure bins. The tails are trimmed until the retained curve ends head
   toward its minimum. Fitting also requires at least four bins, an index range
   greater than 0.2, more than half of the window's observations retained, and
   the minimum-index bin remaining in the fit.
3. Fits a quadratic U-shaped curve to pressure versus correlation. A fit with
    a negative quadratic coefficient is rejected. The fitted minimum is the
    local optimum; the lower/upper limits are the outer pressure values where
    the fitted index is at or below the configured 0.3 threshold.
4. Scores each valid fit by curve shape and index nadir. It ranks the index
    scores high-to-low and curve scores low-to-high, normalizes the ranks, then
    combines the ranked candidates into `Global_Optimal_PPC` (PRx) or
    `Global_Optimal_PAM` (COx), with similarly combined limits. The recap
    includes those values and the time-varying correlation indices.

Both production configurations request a pressure-shift mitigation after
median filtering, but specify `"Pressure shifting"` while the algorithm checks
for the case-sensitive value `"Pressure Shifting"`. As currently written, that
backward pressure shift is not applied.

The worker persists each non-empty, timestamped OptiBrain recap, including
recaps where no global optimum was identified. In that case the stored scalar
optimum and limits remain null while the raw recap remains available for the
patient page; it is not represented as a successful target window. PRx and COx
freshness are tracked independently so a recent result in one mode does not
prevent the other from running. The UI reads the stored raw recap and only
paints a dynamic band when both limits are present, ordered, and recent. A long
result table can therefore contain many rows while having few or no complete
displayable windows.

### Browser-only temporary-import calculation

The temporary patient page deliberately uses a separate, lightweight browser
calculation; it does not call OptiBrain or write `patient_autoregulation`.
It aligns matching timestamps from imported channels, shifts the trace to the
present for charting, computes a 30-sample rolling PIC/PPC (PRx) or NIRS/PAM
(COx) Pearson correlation, bins the index by PPC (PRx) or PAM (COx) in 5 mmHg
bins, and computes rolling optima from the preceding 60 samples at a
one-sample step. Each bin must hold at least two observations and 2% of usable
samples. This browser method does not reproduce the production module's
sampling, window lengths, filtering, scoring, or acceptance behavior.

Consequently, a window shown for an imported fixture demonstrates the
temporary UI path only. Its correlation uses 30 paired samples and its rolling
optimum uses a 60-sample lookback; the 24-hour fixture span extends the chart
coverage but does not increase those computation-window sizes or reproduce
OptiBrain's 5–90-minute correlation grid. It must not be interpreted as a
validated OptiBrain result or as clinical guidance.
